# NCEP BUFR tanks

`bufr-query` mappings for NCEP BUFR tanks, the daily files laid out as
`YYYYMMDD/bAAA/xxBBB`, where `AAA` is the BUFR data category and `BBB` is the local
subcategory. GEODE uses these to ingest the tanks.

| Path | Contents |
|---|---|
| `config/bAAA_xxBBB.yaml` | The mapping for one tank |
| `config/bAAA_xxBBB_<profile>.yaml` | One mapping per profile, for tanks holding several unrelated profiles |
| `aux/bufr_tank_sequence_sizes.yaml` | The largest replication count seen for each BUFR sequence, used when generating the mappings |

The mappings are generated by GEODE's `dev/ush/generate_bufr_tank_yamls.py`, from
`show_queries.x` and `gettab` output for each tank. Dataset names, splits and satellite
names are kept in GEODE.

Most repeated sequences are stored on the `Location` dimension, so that data from
different files can be appended together. See GEODE's `docs/bufr-tanks.md` for how each
kind of sequence is stored.

Variables stored only on `Location` set `chunks: [1000000]`. Without it, `bufr-query`'s
netCDF encoder writes each variable as one chunk, and a tank that pads every report to the
longest one (such as radar) can exceed netCDF's 4 GB chunk limit.
